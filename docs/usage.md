# 使い方ガイド

## 画面構成

初期画面は **同期** です。PCは左側、スマホは下部のナビゲーションで画面を切り替えます。

| 画面 | 用途 |
|---|---|
| 同期 | 登録済み・自動同期が有効・要対応の件数、プレイリストの停止・再開 |
| ダウンロード | URL追加、進捗、失敗した処理の再試行 |
| ファイル | 保存済みファイルの検索・取得・削除・試聴 |
| 設定 | YouTube接続、Syncthing、自動処理・通知、診断、HTTPS設定の案内 |

「同期を追加」で追加欄を開きます。曲一覧・エラー詳細・今すぐ同期・削除は同期プレイリスト一覧の各行をクリックするか「詳細」から右側のパネルで操作します。
パネルは閉じるボタンまたはパネル内でEscapeを押して閉じられます。
画面切り替えでは一覧を作り直さず、試聴プレイヤーは操作したときだけ表示します。

## まとめて追加・復旧・持ち出しの確認

### URLもアカウント内の名前も、同じ入口から追加

**同期 → URL・名前から追加** に、動画・プレイリスト・チャンネルのURLを1行ずつ貼り付けます。一度に20件まで確認できます。接続中のアカウントのプレイリストは名前から検索できます。検索結果が多い場合は名前を絞り込んでください。

**内容を確認** で種類・曲数・重複・取得可否を表示し、選択した対象だけ追加します。公開・限定公開の共有URLはYouTubeへのログイン不要です。非公開プレイリストの公開範囲を勝手に変更することはありません。

動画とチャンネルはダウンロード画面、プレイリストは同期プレイリスト一覧で確認します。ダウンロード画面の「URL・名前からまとめて追加」も同じ入口を開きます。従来の個別追加は折りたたみ欄から利用できます。

確認結果の有効期間は15分です。登録済みでキューへの追加が失敗したものは、ページを閉じた後でも「要対応」から再開できます。未登録のまま期限を過ぎた対象は再確認が必要です。登録後に削除した対象を再試行で勝手に復活させません。

### 保存プロファイル

**設定 → 保存プロファイル** に「スマホ用」「音質優先」「動画保存」の標準設定があります。「コピーして編集」で名前・形式・品質・共有フォルダ・確認する端末をまとめて保存できます。共有フォルダの範囲は、Syncthingで実際に共有しているダウンロード全体か、プレイリストのフォルダ自体に合わせます。プロファイルを選択しても、Syncthingの共有先や公開範囲は変更しません。

追加時にプロファイルを選ぶと、設定をその同期に保存します。プロファイルを編集・削除しても既存の同期は維持します。変更したい場合は **既存同期へ適用 → 対象を選択 → 変更内容と再取得量を確認 → 適用** の順に操作します。適用前に内容が変わった場合やDL中の場合は再確認が必要です。

再取得量の表示は現在のファイル量に基づく目安です。形式変更前のファイルも保持するため、追加の空き容量が必要です。

### エラーを原因別にまとめて解決

同期画面の **要対応** を開くと、認証・通信・取得不可・設定・保存ファイルの消失など、原因ごとの対象と操作を表示します。概要の要対応件数からも開けます。

- 認証切れ: 設定から再接続すると、有効な自動同期をまとめて再試行します。一時停止中の同期は自動再開しません。
- 通信失敗: 自動再試行に加え、対象をまとめて再試行できます。
- 取得できない動画: 今後の取得から除外できます。同期の履歴、または要対応内の「取得から除外中」から戻せます。
- 途中の追加処理: 登録を重複させずにキューへの追加を再開できます。

### 変更履歴と復元

各同期の詳細にある **変更履歴・保留中の曲** で、追加・保留・取得失敗・復元・プロファイル変更を確認できます。同じ原因の連続した失敗はまとめます。履歴は最近100件、保留曲は200件ずつ表示します。

同期元から消えた曲は、既定で7日間ファイルを保留します。期間内なら **復元して保持** でファイルをそのまま戻せます。期限を過ぎた後の定期処理で、アプリの保存領域内にあり、他の記録が参照していないファイルだけ整理します。期限切れ後の復元では再取得します。

復元した曲は同期元から消えたままでも保持します。**保持を解除** すると次回同期で再判定します。保留日数は設定から1～90日に変更でき、すでに保留中の曲にも適用します。

### サーバー保存と端末への到達を区別

プロファイルに共有フォルダと端末を指定すると、各同期に「取得中」「サーバー保存済み」「端末へ転送中」「持ち出し可能」などを表示します。サーバー上の実ファイルを確認し、指定した端末が接続中で、対象ファイルの版・サイズ・更新時刻と端末側の保持情報が一致した場合にだけ、到達済みとします。

フォルダ全体の100%だけで到達済みとは判定しません。端末がオフライン、共有されていない、索引が古い、確認に失敗した場合は未確認と表示します。ファイル情報の確認キャッシュは最大30秒です。「持ち出し可能」は確認時点の状態を示します。

## 1. 音楽をダウンロードする（ダウンロード画面）

### 手順

1. **ダウンロード画面**上部の入力欄に YouTube URL を貼り付ける
2. 表示された保存形式・品質を確認（通常は設定画面に保存した値を使用。その回だけ変える場合は **「今回だけ変更」** を開く）
3. **「追加してダウンロード」** をクリック

登録が完了すると **登録済みのURL** に追加され、バックグラウンドでダウンロードが始まります。

自動同期しているプレイリスト・チャンネルのファイルを「ファイル」画面から削除した場合、その動画が同期元に残っていれば次回の自動同期で再取得します。

### 対応 URL

| 種別 | 例 |
|------|-----|
| 動画 1 件 | `https://www.youtube.com/watch?v=dQw4w9WgXcQ` |
| プレイリスト | `https://www.youtube.com/playlist?list=PLxxxx` |
| チャンネル | `https://www.youtube.com/@ChannelName` |

プレイリスト・チャンネルを登録すると、含まれる全動画がキューに追加されます。

### 進捗の確認

**ダウンロードキュー** にリアルタイムで進捗バーが表示されます。

| 表示 | 意味 |
|------|------|
| `pending` | キュー待ち |
| `downloading` + バー | ダウンロード中 |
| 完了したジョブが一覧から消える | ダウンロード完了。保存済みファイルは「ファイル」画面で確認 |
| `failed` + ↺ | 失敗（↺ でリトライ） |

ワーカー停止などで処理が中断した場合は、キューの表示・進捗通知時に状態を確認します。開始から10分以上経過してタスクの失敗・取消が確認できたジョブは、再試行可能な `failed` に切り替わります。タスク状態が不明な場合は、開始から2時間以上経過し、進捗が途絶え、応答したワーカーの実行一覧にも見つからない場合に切り替わります。実行中の変換や、ワーカーから応答がないだけの場合は失敗扱いにしません。

### URL の削除

**登録済みのURL** の各行の **✕** をクリックします。ダウンロード済みファイルは削除されません。

## 2. 保存済みファイルを管理・試聴する

1. **ファイル**画面でタイトルやアーティスト名を検索
2. 聴きたいファイルの **試聴** を押して、そのファイルを再生
3. 小さな操作欄で再生・一時停止・シークを操作。**✕** で停止して閉じる

行のクリックだけでは再生しません。再読み込み時も試聴欄は自動表示しません。

### トラック操作

| ボタン | 動作 |
|--------|------|
| **↓** | 音声ファイルをブラウザにダウンロード |
| **🗑** | DB レコード・ファイル・サムネイルをすべて削除（確認あり） |

## 3. YouTube プレイリストを自動同期する（同期画面）

### 他の人の公開・限定公開プレイリストを追加する

1. YouTubeで対象プレイリストの共有URLをコピー
2. **同期 → 同期を追加 → 共有URLから追加** に貼り付ける
3. **同期追加** をクリック

自分が所有していないプレイリストでも利用できます。YouTubeアカウントへのログインは不要で、設定画面でAPI方式を選択していても、この追加欄は共有URLで取得します。非公開プレイリストは共有URLだけでは取得できません。

### 自分のアカウントから選ぶ場合の認証

=== "方法 A: OAuth2 で接続（推奨）"

    1. **設定**画面の **「YouTubeアカウントに接続」** をクリック
    2. Google のログイン画面でアカウントを選択・許可
    3. 認証後に設定画面で接続状態を確認

    !!! note "事前準備"
        `.env` に `YOUTUBE_CLIENT_ID` と `YOUTUBE_CLIENT_SECRET` の設定が必要です。  
        → [環境設定 > YouTube OAuth2 設定](deployment/configuration.md#youtube-oauth2-設定)

=== "方法 B: トークンを直接入力"

    `YOUTUBE_CLIENT_ID` / `YOUTUBE_CLIENT_SECRET` なしで利用できます。

    1. **「トークンを直接入力」** をクリック
    2. [Google OAuth 2.0 Playground](https://developers.google.com/oauthplayground/) でトークンを取得
        - Step 1: `https://www.googleapis.com/auth/youtube` を入力（非公開→限定公開の切替も行う場合。読み取りのみなら `youtube.readonly`）
        - **「Authorize APIs」** → **「Exchange authorization code for tokens」** を実行
        - **Access token** をコピー（必要なら **Refresh token** も）
    3. フォームに貼り付けて **「保存」** をクリック

    !!! tip "トークンの更新"
        **「トークンを更新」** ボタンから同フォームを再度開けます。  
        Access Token の有効期限は通常 1 時間です。

### プレイリストの同期追加

1. **同期を追加** を開き、「アカウントのプレイリスト」から同期したいプレイリストの **「+ 同期追加」** をクリック
2. 「同期中のプレイリスト」に追加され、ダウンロードが自動開始

保存形式・品質・公開プレイリストの取得方式は、**設定 → ダウンロード・取得方式** に保存した値を使用します。非公開プレイリストはAPI方式を初期選択し、公開範囲を自動では変更しません。追加ダイアログの **「今回だけ設定を変更」** から、その同期だけ別の形式や方式を選べます。

### DLと取得方式の設定

**設定 → ダウンロード・取得方式** で次の項目を保存できます。

| 項目 | 選択肢 |
|------|--------|
| 保存形式 | MP3 / M4A / FLAC / AAC / OGG / MP4 / WEBM |
| 音声の品質 | 192 kbps / 320 kbps / 最高品質（動画形式では使用しません） |
| アカウントのプレイリスト取得方式 | 共有URL / YouTube API |

保存内容はサーバーに保持し、新しく追加する同期とダウンロードに適用します。既存の同期設定・ファイル形式は変更しません。APIから追加する場合も、形式・品質を省略すると保存済みの値を使用し、明示した値があればそちらを優先します。


### 同期設定の管理

| ボタン | 動作 |
|--------|------|
| **同期** | 自動同期が一時停止中でも、今回の同期を1回実行 |
| **一時停止 / 再開** | 自動同期の有効・無効を切り替え |
| **削除** | 設定を削除（ファイルも削除するか選択可） |
| **トラック一覧** | 同期済みトラックの一覧を展開 |

手動の「同期」では自動同期の有効・無効は変更しません。

同期トラックの停滞は、登録時刻と実際のダウンロード開始時刻を分けて判定します。長い待機後に開始した処理や、進捗がある処理、ワーカーで実行中の変換は、登録から2時間を超えていても失敗扱いにしません。開始時刻を記録していない更新前のダウンロードや、ワーカーの状態を確認できない処理も、経過時間だけでは失敗扱いにしません。

同期の追加・一時停止・再開では、表示しているプレイリスト一覧を消さず、変更したカードと同期バッジを更新します。
開いているトラック一覧・エラー詳細やスクロール位置も維持します。
同期画面を表示している間は、件数・完了状態・エラーと、開いている詳細内のトラック一覧を5秒ごとに自動更新します。別の画面や非表示タブでは更新を止めます。取得に失敗しても現在の一覧と開いた詳細を残し、次の更新で再確認します。アカウントのプレイリスト取得APIは自動更新しません。

手動同期と定期同期が重なっても、同じ同期・トラックの処理はワーカー間の共有ロックで1件ずつ実行します。自動同期を一時停止すると未開始のDLは待機に戻り、再開後の同期で取得します。開始済みのDLは完了させます。「同期」で明示的に依頼した1回分は一時停止中でも実行します。

[並行実行・コンテナ検証の手順](sync-testing.md)も参照できます。

ワーカーが異常終了した場合は、ロックの有効期限（通常120秒）が切れた後、次の手動同期・定期同期で中断したDLを再取得します。処理中に「ファイルも削除」を選んで同期を削除した場合、遅れて完了したファイルも公開しません。「設定のみ削除」の場合はファイルを残します。

YouTube側でプレイリストを変更した場合は「アカウントのプレイリスト」の **更新** を押してください。
ダウンロード件数などを再取得する場合は「同期中のプレイリスト」の **更新** を使います。
再取得に失敗した場合は現在の一覧を残し、一覧の上にエラーを表示します。

自動同期間隔は「自動同期間隔 / YouTubeプレイリスト」セレクターで変更できます（手動のみ〜24時間）。

## 4. Syncthing でモバイルに同期する

`downloads/` フォルダを Syncthing で共有すると、スマートフォンに音楽ファイルを自動転送できます。

### セットアップ手順

1. PC とスマートフォンに [Syncthing](https://syncthing.net/) をインストール
2. PC の Syncthing GUI（`http://localhost:8384`）を開く
3. 設定 → API キーをコピーして `.env` の `SYNCTHING_API_KEY` に設定
4. `downloads/` フォルダを共有フォルダとして追加
5. スマートフォン側でデバイスとフォルダを承認

画面右上の **Syncthing バッジ** で同期状態を確認できます。

| バッジ | 意味 |
|--------|------|
| `Syncthing: off` | 未設定または接続不可 |
| `Syncing…` | 同期中 |
| `Synced 100%` | 同期完了 |

## 5. 自動同期間隔を設定する

**Queue パネル下部の「自動同期間隔 / URLキュー」** セレクターで、登録 URL（プレイリスト・チャンネル）の定期チェック間隔を設定します。

| 設定 | 動作 |
|------|------|
| 手動のみ | 自動チェックしない |
| 15分〜24時間 | 指定間隔で全 URL を再チェックし、新着動画を自動ダウンロード |

## 6. 管理操作

### DB とファイルシステムの同期

ファイルを手動削除したなど、DB にレコードがあるがファイルが存在しないトラックを一括削除します。

```bash
curl -X POST http://localhost:8000/api/v1/admin/rescan
# → {"removed": 3}
```

### ヘルスチェック

```bash
curl http://localhost:8000/api/v1/health
# → {"status":"ok","redis_connected":true,"db_ok":true,"worker_active":true}
```

| フィールド | 説明 |
|-----------|------|
| `status` | `ok`（正常）または `degraded`（Redis/DB 障害） |
| `redis_connected` | Redis 接続状態 |
| `db_ok` | DB 接続状態 |
| `worker_active` | Celery ワーカーの応答状態 |

## 7. よくある問題

??? question "URL を登録してもダウンロードが始まらない"
    Celery ワーカーが起動しているか確認してください。  
    `GET /api/v1/health` で `worker_active: false` の場合はワーカーを再起動します。

    ```bash
    docker compose restart worker
    ```

??? question "ダウンロードが `failed` になる"
    - **ダウンロードキュー** の `failed` ジョブの **↺** でリトライできます
    - 非公開・削除済み動画は再試行しても失敗します
    - yt-dlp のバージョンが古い場合は更新が必要です

??? question "音楽が再生できない"
    トラックカードをクリックしても再生バーが表示されない場合、音声ファイルが存在しない可能性があります。
    ```bash
    curl -X POST http://localhost:8000/api/v1/admin/rescan
    ```

??? question "YouTube 認証が失敗する"
    以下を順番に確認してください。

    **「このアプリは Google で確認されていません」と表示される**  
    Google Cloud Console の OAuth 同意画面で「テストユーザー」に自分の Google アカウントを追加してください。
    テストユーザー未登録の場合、認証がブロックされます。

    **「redirect_uri_mismatch」エラーが出る**  
    `.env` の `YOUTUBE_REDIRECT_URI` と Google Cloud Console の「承認済みリダイレクト URI」が完全一致していることを確認してください。
    末尾スラッシュ・http/https の違いも含めて一字一句同じである必要があります。

    **localhost 以外のホストでリダイレクト URI が解決できない**  
    ブラウザを動かしているマシンの `/etc/hosts`（Windows: `C:\Windows\System32\drivers\etc\hosts`）に
    サーバーのホスト名と IP の対応を追加してください。
    → 詳細: [リダイレクト URI の設定（環境別）](setup/external-services.md#リダイレクト-uri-の設定環境別)

    **プレイリストの取得が「チャンネルが見つかりません」などのエラーになる**  
    認証に使った Google アカウントに YouTube チャンネルが開設されていることを確認してください。
    Google アカウントがあっても YouTube チャンネル未作成のアカウントでは API 呼び出しが失敗します。
    → [YouTube チャンネルを作成する](https://support.google.com/youtube/answer/1646861)

    **上記以外**  
    - `.env` の `YOUTUBE_CLIENT_ID`・`YOUTUBE_CLIENT_SECRET` が正しいか確認
    - YouTube Data API v3 が Google Cloud Console で有効化されているか確認

??? question "認証済みなのに 401 / 502 エラーでプレイリストが取得できない"
    認証後しばらくして突然エラーになる場合は、トークンが失効している可能性があります。
    最も多い原因は **OAuth 同意画面「テスト」モードによるリフレッシュトークン 7 日失効** です。

    → 詳細な原因別チェックリスト: [YouTube API 401 エラー チェックシート](setup/external-services.md#youtube-api-401-エラー-チェックシート)

??? question "Syncthing バッジが「off」のまま"
    - `SYNCTHING_API_KEY` が設定されているか確認
    - Syncthing が起動しているか、`SYNCTHING_URL` が正しいか確認

### YouTube トークンの状態を確認する

YouTube の接続欄には、アクセストークンの期限、更新トークンの有無・期限、最終更新成功日時を別々に表示します。
「接続を確認」は更新トークンを使って実際にアクセストークンを更新します。通常の状態表示では Google への確認は行いません。
API 利用時にも、アクセストークンの期限が近ければ自動更新し、その結果を保存します。

- **再認証が必要**: Google が更新トークンを拒否した場合など。OAuth で再接続してください。
- **設定を確認**: OAuth クライアントの設定が不足、または Google に拒否されています。
- **一時的な失敗**: 通信失敗など。回復後に接続確認を再試行できます。
- **更新トークン期限が不明**: Google が期限を返していません。無期限を保証する表示ではありません。

Google の公開ステータスは自動取得できません。テストモードを使用している場合は `.env` に
`YOUTUBE_OAUTH_PUBLISH_STATUS=testing` を指定すると、OAuth フローで新しく更新トークンを取得した日時から7日を期限の**目安**として表示します。
本番モードでは `production`、不明な場合は既定の `unknown` を使ってください。変更後はAPI・worker・beatを再作成してください。
この設定は Google 側の公開ステータスを変更せず、7日の制限も解除しません。
既存トークンや直接貼り付けたトークンの取得日時は推測しないため、OAuth で再認証するまでは目安も不明です。
Google が明示的な期限を返した場合は、その期限を優先します。
自動更新できるアクセストークンの短い期限だけでは再認証通知を送りません。

### 追加・実行・削除の結果を確認する

同期を追加すると、プレイリスト名と「追加した同期を見る」が表示されます。
このボタンで追加した行へ移動でき、通知は閉じるボタンで消せます。
詳細パネル内で同期を実行した場合、そのパネル内に依頼中・キュー登録済み・失敗理由を表示します。
キュー登録済みは同期の完了を意味しません。
ファイル削除に失敗した場合は対象行に理由が表示され、「削除を再試行」から確認後に再実行できます。
失敗しただけでは一覧を消したり、他のファイルを削除したりしません。

同期追加欄のYouTube案内は接続状態に応じて変わります。認証情報がある場合は追加方法、未接続なら設定への接続案内、更新拒否時は再認証の案内を表示します。通信失敗は未接続や認証切れと断定せず、接続状態の確認を案内します。

同期プレイリスト一覧は行全体から詳細を開けます。一時停止・再開ボタンや詳細パネル内の操作では、行クリックの処理は実行しません。キーボードでは右端の詳細ボタン（矢印）を使用できます。

### 大きな同期プレイリストの確認

詳細で曲一覧を開くと50曲ずつ表示します。「前へ」「次へ」で移動でき、タイトル・アーティスト名と状態で絞り込めます。自動更新中もページや検索条件を保ちます。取得に失敗した場合は表示を残し、「再試行」から取得し直せます。

ファイル・ダウンロード・設定のデータは、必要な画面を初めて開いたときに読み込みます。アカウントのプレイリストは追加欄の「アカウントから選ぶ・個別に追加」を開くと取得します。
