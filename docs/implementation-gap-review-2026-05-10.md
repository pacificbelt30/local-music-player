# 実装・ドキュメント点検（2026-05-10）

本ドキュメントは、現行実装（FastAPI/Celery/yt-dlp/Syncthing）と既存ドキュメントを突き合わせて、
実装漏れリスクと追加要件候補を整理したものです。

## 1. 前提と方針

- 配信元は **YouTube のみ**。
- 利用経路は **ローカル LAN** と **Tailscale 経由 VPN** を主対象。
- 公開インターネットに直接晒す前提ではない。

## 2. 実装済みで、要件に対して有効な点

- URL 入力は YouTube ドメインのみを受け入れるバリデーションになっている。
- `SECRET_TOKEN` による Bearer 保護が API 全体に適用できる。
- `ALLOWED_ORIGINS` をカンマ区切りで指定でき、Tailscale 用オリジン制限に対応可能。
- Syncthing 連携は API キー未設定時に無効化される設計で、段階導入しやすい。

## 3. 実装漏れ/運用漏れになりやすいポイント

### 3.1 セキュリティ初期値が開放的

- `ALLOWED_ORIGINS` のデフォルトが `*`。
- `SECRET_TOKEN` のデフォルトが空（無認証）。

ローカル用途では開発しやすい一方、Tailscale 共有時は最低でも以下が必要。

- `ALLOWED_ORIGINS` を `http://<tailscale-ip>:8000` 等に限定
- `SECRET_TOKEN` を長いランダム値に設定

### 3.2 ストリーミング API のアクセス制御はトークン依存

`SECRET_TOKEN` 未設定だと `/stream/*` も公開状態になるため、
「LAN 内だけだから安全」という運用に依存しやすい。

### 3.3 YouTube OAuth2 のリダイレクト URI 管理

- `YOUTUBE_REDIRECT_URI` はアクセス URL と厳密一致が必要。
- LAN URL / Tailscale URL / localhost を混在運用すると設定不一致が起きやすい。

### 3.4 ダウンロード実行の同時数制御が弱い ✅ 対応済み

- **実装済み**: `celery_worker_concurrency` 設定（0 = CPU コア数に合わせて自動）を追加。
- 設定画面から変更可能。変更はワーカー再起動後に反映。

### 3.5 監視・障害通知が薄い ✅ 対応済み

- **実装済み**: Discord Webhook 通知を実装。
- 設定画面の「Discord Webhook URL」に URL を入力し、「Discord 通知イベント」チェックボックスで通知対象を選択。
- 対応イベント: ダウンロード完了・失敗、DB 障害、YouTube OAuth 認証切れ。
- DB 障害時は DB から設定が読めないため `DISCORD_WEBHOOK_URL` 環境変数をフォールバックとして使用。

## 4. 追加要件として有用な候補（優先順）

### P1（先にやると効果が高い）

1. **セキュア初期設定ウィザード**
   - 初回起動時に `SECRET_TOKEN` と `ALLOWED_ORIGINS` 未設定なら警告表示。
   - Tailscale 利用時の推奨値を UI で提案。

2. **接続プロファイル機能（Local / Tailscale）**
   - CORS/表示 URL/OAuth リダイレクト URI の設定テンプレート化。
   - 切替時に必要差分をチェックリスト表示。

3. **同期・DL失敗の通知**
   - 最低限 Webhook（Discord/Slack）対応。
   - 失敗連続回数のしきい値通知。

### P2（運用快適性）

4. **帯域・時間帯制御**
   - 夜間のみ同期、モバイル接続時抑制など。

5. **重複/低品質フィルタ強化**
   - 同一動画の再取り込み抑止ルールを明示化。
   - 長さ・タイトルキーワードで除外フィルタ。

6. **ダウンロード優先度キュー**
   - 今すぐ聴きたい曲を優先する手動優先度。

### P3（拡張）

7. **メタデータ品質改善**
   - アーティスト/アルバム名推定の補助ロジック。

8. **バックアップ/リストア導線**
   - DB と設定のエクスポート/インポート。

## 5. Tailscale 前提の最小推奨運用

1. `.env` で `SECRET_TOKEN` を設定（32 文字以上推奨）。
2. `ALLOWED_ORIGINS` を使用する URL のみに限定。
3. `YOUTUBE_REDIRECT_URI` を実際に使うホスト名で統一。
4. Syncthing GUI（8384）を不用意に公開しない（必要時のみ到達）。
5. 定期的に失敗ジョブ件数を確認（将来は通知で代替）。

## 6. 結論

現状のコードベースは「YouTube 限定・ローカル同期用途」の中核要件は概ね満たしています。
一方で、Tailscale を含む実運用での体感品質を上げるには、
**セキュア初期設定の強制力**と**障害可視化（通知）**を優先的に追加するのが効果的です。

## 7. 類似サービス調査（比較観点）

このプロジェクトの立ち位置（YouTube 起点でローカル保存し、手元再生 + モバイル同期）に近い
OSS を調査し、機能差分を整理します。

### 7.1 比較対象

- **TubeSync**: YouTube チャンネル/プレイリストの継続同期に特化した PVR。
- **Navidrome**: ローカル音楽ライブラリの配信・再生体験に特化したサーバー。
- **Jellyfin**: 動画含む総合メディアサーバー（音楽機能も有する）。
- **MeTube**: yt-dlp の軽量 Web UI（単発ダウンロード向き）。

### 7.2 ざっくり比較

| 観点 | 本プロジェクト | TubeSync | Navidrome | Jellyfin | MeTube |
|---|---|---|---|---|---|
| YouTube の定期取得 | ◎（URL/プレイリスト同期） | ◎（主機能） | ✕（取得機能なし） | ✕（取得機能なし） | △（手動中心） |
| 音楽再生 UI | ○（シンプル） | △（主目的は収集） | ◎（音楽特化） | ○（総合型） | ✕ |
| モバイル同期（ファイル実体） | ◎（Syncthing 前提） | △（別途連携） | △（クライアント依存） | △（クライアント依存） | ✕ |
| 初期導入のわかりやすさ | ○ | ○ | ○ | △（機能広く設定多め） | ◎ |
| 「YouTube限定の自分用保管」適性 | ◎ | ◎ | △ | △ | ○ |

### 7.3 差別化ポイント（維持すべき強み）

1. **YouTube 取得 + ローカル再生 + Syncthing 同期**を1つの文脈で扱える。
2. 「音源を手元に残す」運用に向いており、クラウド依存が少ない。
3. Tailscale を併用した閉域運用と相性が良い。

## 8. さらに追加できる便利機能（実装候補）

※「いきなり実装」ではなく、要件として合意してから着手する前提。

### 8.1 操作体験（最優先）

1. **Syncthing 初期設定ガイドモード**
   - 画面に「次の1手」を表示（APIキー確認 → フォルダ共有 → 端末承認）。
   - 設定不備を人間向けメッセージで表示（例: URL誤り、キー未設定）。

2. **ダウンロード元 URL のプリセット化**
   - よく使うプレイリストをテンプレ保存。
   - 1クリックで有効/無効切替。

3. **失敗ジョブの再実行バッチ**
   - 失敗理由ごとに一括リトライ（ネットワーク系のみ再試行など）。

### 8.2 品質改善

4. **メタデータ補完（任意）**
   - タイトル正規化ルール（`[Official]` 除去など）を UI 設定化。
   - ジャケット欠損時のフォールバック画像生成。

5. **音量差の自動平準化プロファイル**
   - 現在の gain 設定に加え、プリセット（軽め/標準/強め）を提供。

### 8.3 運用改善

6. **通知チャネル連携（Webhook）**
   - 同期成功/失敗サマリを Discord/Slack 通知。

7. **バックアップ支援**
   - DB・設定・プレイリスト定義のエクスポート/インポート。

8. **Tailscale 利用チェック**
   - 接続元が Tailscale 想定と一致しているかのセルフチェック表示。

## 9. 推奨する次アクション

1. 上記 8.1 の3項目から、まず 1 つだけ選んで要件確定。
2. 画面モック（ワイヤーフレーム）を先に合意。
3. API 変更が必要なら、先に OpenAPI 仕様とテストケースを決める。
4. 実装後は「ローカルのみ」「Tailscale 経由」の2経路で受け入れ確認する。
